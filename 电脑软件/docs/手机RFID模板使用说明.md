# CUID/FUID 手机写卡与可重复资料卡说明

更新：2026-09-09。当前客户端数据库 schema 为 **56**，个人库存 API 的服务端 migration 为
**27**。本文描述当前契约；旧 APK、旧服务端或旧的 NTAG 耗材工具文档不适用。

## 标签职责

| 标签 | 当前职责 | 明确不做的事 |
| --- | --- | --- |
| **CUID/FUID**（4 字节 UID 的 MIFARE Classic 兼容卡） | 读取耗材资料卡、写入兼容 AMS 模板、登记库存、保存每卷余量、消耗和换卷历史 | 不把相同 UID 当成两张可自动区分的实体卡 |
| **NTAG213** | 独立的打印机设备工作台入口：定位设备、查看状态/故障、记录维护 | 不写耗材资料，不登记库存，不参与余量、消耗或换卷 |

选择 CUID 或 FUID 是对所购卡型的明确确认。手机读到 UID 和 MIFARE 结构，不能仅凭一次扫描自动证明商品卡型；普通 S50、NTAG213 和未确认的 Classic 不得进入耗材流程。

## 两条 CUID/FUID 流程

### 1. 读取资料卡，批量新增库存

这是重复使用同一张 CUID/FUID 资料卡的入口，**读取不会改写标签**。

1. 在手机或桌面个人版的库存页选择“批量加库存”，选择“读取 CUID/FUID”，扫描一张已确认的资料卡。
2. 核对品牌、型号、材质、颜色和实际入库方式。按卷数入库时选择 **1–100 卷**；当前整卷模式按每卷 1000 g（1 kg）登记。按余量入库时只登记一卷并填写实际余量（大于 0 且不超过 1000 g）。
3. 点击确认后，系统为本批每一卷生成独立的库存 UID，并写入来源资料卡 UID、卡型、批次操作 UID 和批次序号。来源 UID 只是“这批资料从哪张卡读取”的凭据，不会把所有卷绑定为同一卷，也不会自动占用 AMS 槽位。
4. 扫描成功后可以点击“取消”或从桌面待办中移除。取消在确认前不创建库存、不写入库存事件，也不会增加余量。

同一张 CUID/FUID 卡可以在以后再次读取。每次新入库必须生成新的操作 UID；同一操作 UID 的重试是幂等的，只核对原批次，不会重复增加卷数。已经消耗、替换或归档的卷不会因为再次读取资料卡而被补满或复活。若要补货，应重新确认数量并提交一个新批次。

手机离线时先保存本机库存和待同步事件；联网后同步同一账号。账号切换、离屏或取消时，迟到的 NFC 回调不会提交到新账号。

### 2. 写入兼容模板，登记当前实物卷

“兼容标签模板”是另一条流程：用户读取自己持有的完整 AMS 源标签，或导入完整 1 KB 模板，再将模板恢复到已确认的 CUID/FUID 目标卡。应用保留源 UID、64 个块、密钥/访问位和签名区域，不生成厂商签名，也不把自填品牌、型号、颜色写进厂商数据。

完整写入、回读 64 块和真实 UID 校验通过后，写入页会登记**当前这卷实物耗材**，并记录当前标签周期。它不是批量加库存入口；同一张资料卡要为后续到货增加多卷时，请回到库存页使用上面的“读取 CUID/FUID”流程。重复写卡不会自动给旧卷补重量；耗材换新时在库存详情明确创建下一周期，旧卷的余量与消耗账保留。

FUID 的 block 0 通常只有一次写入机会，可能无法恢复。写卡中断、拒写或回读失败时，应用不会登记成功；请隔离该卡并保留源模板，不要自动重试或直接放入 AMS。

## AMS 绑定、余量和换卷

- 批量读取生成的库存行先只有“来源资料卡”字段，当前物理标签绑定字段为空。这样一张卡可对应多卷库存而不会互相覆盖。
- AMS 上报的完整 `tag_uid`、模板 `tray_uuid` 和手机读到的短 UID 是不同标识。首次遇到长短 UID 候选时，必须在桌面选择具体库存卷并确认；不唯一、跨账号、已结束周期或冲突候选均拒绝自动猜测。
- 选择一卷进行装机时，系统在事务中把当前 CUID/FUID 标签绑定到该卷；换卷会结束旧周期、创建下一周期并保留前驱卷号、任务段和全部消耗事件。多卷候选不会因为共用来源 UID 而合并。
- 同一 UID 的克隆卡在软件上无法靠上报值区分。不要把两张相同 UID 克隆卡同时放入不同槽位并期待自动逐卡追踪；需要人工核对正在使用的实物卷。
- 消耗以打印估算、AMS 进度和人工称重事件分别记录；软件测试不能替代逐克称重。回库或余料换绑不重新计为采购入库。

### 检测到取下与再次装入时

例如一卷初始 1000 g，已用 585 g，账面还剩 415 g：

- 检测到取下时先暂停扣料，保留这卷的 415 g、独立卷号和未结算任务。取消弹窗也不会清空余量。
- 明确选择“维修暂取”后，装回原卷可从保留的余量继续；普通取下回库或准备换卷后，重复使用的卡号不能直接证明装回的是原卷，需要确认具体库存卷。
- 再次装入时可选择原来的 415 g 余料卷，也可选择同卡下另一卷已入库库存。选原卷不补满、不新增库存；切换另一卷时，旧卷余量保留，当前打印任务按实际使用的两卷分段记录。
- 只有明确选择“已用完”并再次确认才执行耗尽结算。确认期间若检测到重新装入，旧的耗尽操作作废。
- 每一实物卷固定为 1000g；500g、750g 表示该卷的实际剩余量，不是另一种容量规格。余量严格大于 30g 才能继续使用或重新装入，30g 及以下的记录保留供核对，明确确认用完才清零。批量补货仍使用“读取资料卡”入口。

同卡多卷仍需用户辨认实际装入哪卷，软件显示库存卷号与余量供核对；一张反复使用的卡无法独自测量或识别每个未贴独立标识的实物卷。

## 保存、同步与数据边界

- 完整模板、原始块和密钥只按账号加密保存在手机本机，排除 Android 自动备份，不上传 Sohun 云端。
- 云端个人库存只接收品牌、型号、颜色、每卷余量、来源资料卡 UID/卡型、批次回执、当前标签周期和消耗事件；拒绝原始 NFC 块、密钥、签名和凭据。
- 来源资料卡字段是只追加的来源证明，不能被旧客户端的空字段擦除；批次回执账本保证重复上传不会生成副本。
- 账号归属使用服务器地址与稳定用户 ID。使用同邮箱重新注册或在另一服务器登录，不会自动接收旧账号本地库存；旧弹窗在账号切换后不能继续修改库存。无法证明归属的早期邮箱库存保留待核对，不自动上传。
- 本地数据库需升级到 schema 56，服务端需 migration 27，才能保存批次来源账本。只升级手机或只升级桌面不能形成完整跨端链路。

## 实机边界

自动化测试覆盖取消、幂等重试、1–100 卷、余量入库、账号隔离、换卷分段和 NTAG 类型拒绝；它不能证明具体手机 NFC 芯片、CUID/FUID 批次、AMS 固件或打印机已经兼容。正式使用前要用实际源标签、目标卡、打印机和一卷真实耗材验证读写、换槽、断连、重扫、余量及云同步。

NTAG213 的制作和读取步骤见 [NTAG213 设备工作台使用说明](NTAG213设备工作台使用说明.md)。该标签只打开设备工作台，绝不进入上述耗材模型或库存接口。
