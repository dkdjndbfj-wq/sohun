## Bambu Studio native editor handoff

The personal project workspace can launch the user's locally installed
`bambu-studio.exe` with the selected source `.3mf`. The Flutter application
does not link against or bundle `BambuStudio.dll`; the native wxWidgets/OpenGL
editor remains a separate process. Any future installer that bundles Bambu
Studio or its libraries must carry the exact upstream license and source-code
obligations for that version.

## Bambu networking component and certificate

- Local paths:
  - `assets/bin/bambu_networking.dll`
  - `assets/bin/slicer_base64.cer`
- Apparent source: the optional Bambu Studio networking component
- Exact binary version: not recorded in this repository
- License: not established by this repository
- Redistribution status: not cleared

The Bambu Studio README states that its optional networking plugin is based on
non-free libraries. The Bambu Studio AGPL license must not be assumed to grant
redistribution rights for this binary. The current files remain in the private
test workspace because the integration is explicitly retained, but they are a
release blocker until written permission or another valid redistribution basis
is documented.

The local `bind_tool.exe` and `switch_user_tool.exe` wrappers are also part of
this integration. `scripts/build_native_account_tools.ps1` compiles their
checked-in C++ sources on each Windows product build, using only the minimal
callback declarations in `research/account_tool_callbacks.h` rather than a
full vendor SDK header. Runtime checksums are regenerated after compilation.
Their ABI compatibility, build provenance and the implications of loading the
component above must still be verified before distribution. No redistribution
permission for the networking DLL is implied by this build change.

## Microsoft Visual C++ app-local runtime

- Build source: the selected Visual Studio toolset's `VC/Redist/MSVC` CRT
  directory, located by CMake `InstallRequiredSystemLibraries`.
- Bundled files: retail `msvcp140*.dll`, `vcruntime140*.dll`, `concrt140.dll`
  and `vccorlib140.dll` when provided by that toolset.
- Per-build provenance: `msvc-runtime.sha256` beside the application records
  the exact redistributed bytes. No runtime is taken from Windows System32,
  and `Debug_NonRedist` files are not included.
- Extracted Windows helpers copy the same bundle beside their executables;
  they do not rely on the end user having Visual Studio installed.
- Official deployment guidance:
  https://docs.flutter.dev/platform-integration/windows/building
- Build-module reference:
  https://cmake.org/cmake/help/latest/module/InstallRequiredSystemLibraries.html

Before public distribution, verify the applicable Microsoft redistributable
license/REDIST list for the exact installed build tools and include required
notices in the release clearance record. Adding app-local DLLs is not itself
evidence that the release's redistribution obligations have been reviewed.

## Release gate

Do not publish or commercially distribute a build containing uncleared resources until all entries
marked "not cleared" have been resolved and the resulting source, notices, and
license texts are included as required. This gate does not remove or disable
the retained integration during private testing.

The full vendor-integration `build_release.ps1` script enforces this rule. It requires a
machine-readable manifest accepted by `scripts/Test-ReleaseClearance.ps1` and
a real Windows code-signing certificate. `release-clearance.example.json` is
an intentionally failing template, not evidence of permission and not a
clearance artifact.

The separately marked Core Preview is built only from the sanitized public
source export. `scripts/Test-CoreSource.ps1`, the complete source-export
manifest verifier and `scripts/Test-CoreBundle.ps1` must confirm that all
uncleared material above is absent. Its unsigned Windows artifacts and Android
debug APK may only be published as a GitHub prerelease; this does not clear or
relax the formal release gate.

The first formal public core release is built with
`scripts/public_core_build.ps1 -PublicRelease` from the same sanitized source
boundary. It continues to exclude every uncleared resource above. Windows
Release artifacts are explicitly unsigned; the Android Release APK requires a
persistent signing key and certificate fingerprint verification. Source-export,
private-data and bundle checks remain mandatory. Signing secrets are injected
only into temporary build locations and are never shipped.
