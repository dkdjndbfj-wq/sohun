# sohun 验证

根据变更涉及的行为选择验证范围，交付可复现的结果与剩余阻碍。

- 先看变更及最近失败输出，再查 [开发工作流](../../../docs/development-workflow.md) 对应行。该文档是命令入口，不需要读取全部历史审计或设计文档。
- 局部修复优先运行直接相关测试；需要子系统回归时使用 `scripts/verify_all.ps1 -Scope ...`，已有依赖可加 `-SkipInstall`。无参是全仓验收，只在范围需要时使用。
- 桌面与 Android 共用 Dart 工程；Android NFC、原生插件、入口或打包变化还需 Android 构建。`手机软件` 的 Vite 构建不能验证这些行为。
- Windows Flutter 测试保持 `--concurrency=2`：历史数据库迁移测试在默认并发下会耗尽原生资源。库存 HTTP 专项用本地隔离 API，先准备社区服务依赖。
- 若失败来自工具缺失、下载或构建缓存，保留错误证据并使用现有构建脚本诊断；核对缓存完整性，不绕过校验。仅修复与当前任务相关的问题。
- 检查通过即推进交付；未执行的检查说明原因。真机 NFC/AMS 兼容性和公开发布资格分别依赖实测与现有发布门禁，不从单测通过推断。
